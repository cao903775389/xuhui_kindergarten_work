# 上海家庭第一阶段落地执行方案架构 Review

更新时间：2026-05-09

## 总体判断

当前项目已从单一区域择园页面升级为区级落地决策数据产品：以每区统一源数据为输入，串联标准化幼儿园数据集、政策来源、高德 POI/距离、贝壳租房参数、区域路线评分和网页/Excel 输出。

当前架构可以继续支撑“90 天落地执行方案”，但需要坚持一个原则：新增能力先进入标准数据层，再进入策略层，最后进入 UI。不要再把新数据直接写成页面文案或散落在推荐卡片里。

## 当前核心逻辑

### 数据采集层

- 状态：已扩展
- 输入：每区统一源数据文件、官方/公开名单、徐汇 2026 招生计划、闵行/浦东公开名单、贝壳参数、高德 API 查询结果
- 输出：标准化 JSON、CSV、Excel、HTML
- 风险：部分公开名单年度口径不同，尤其闵行民办需报名季复核。

### 标准数据层

- 状态：本次优化
- 输入：data/district_kindergarten_sources/xuhui.json、minhang.json、pudong.json
- 输出：data/kindergartens/kindergarten_dataset.json；data/kindergartens/xuhui_kindergartens.json
- 风险：后续新增区域必须先补标准字段，不应直接写 UI 文案。

### POI 与通勤层

- 状态：已接入
- 输入：园所名称、园区、地址、办公点坐标
- 输出：高德 POI/地址坐标、经纬度、到西岸网易研发中心直线距离
- 风险：直线距离不是实际通勤；地址地理编码不等于 POI 精确匹配。

### 租房联动层

- 状态：已结构化
- 输入：贝壳一级区/二级商圈 slug 与固定筛选 token
- 输出：整租、0-10000、三居/四居+、100㎡以上、有电梯的结构化链接
- 风险：贝壳库存和价格实时变化，页面只保存查询条件，不固化房源。

### 推荐策略层

- 状态：可解释
- 输入：家庭约束、区域画像、公办材料风险、民办兜底、租房可执行性、通勤距离
- 输出：徐汇/闵行/浦东区级择园策略、每区公办争取线、每区民办兜底线、行动清单
- 风险：不承诺精确录取概率，只做政策顺位和执行可行性分层。

### 展示与发布层

- 状态：已发布
- 输入：标准数据、策略文案、来源和质量状态
- 输出：GitHub Pages HTML、Excel、CSV、JSON 数据文件
- 风险：静态页面无法自动刷新实时房源，需要手动重新生成和部署。


## 本次架构优化

- 把徐汇数据从生成脚本迁移到 data/district_kindergarten_sources/xuhui.json，与闵行/浦东保持同一源数据结构。
- 新增数据集 schema，明确后续新增行政区和模块的字段边界。
- 新增网页端架构模块和三区择园策略模块，用信息流式卡片展示核心模块、输入输出和风险。
- 新增架构评审文档和架构 JSON，方便后续迭代时先改数据层，再改策略层，最后改 UI。
- 保留静态站发布路径，同时发布标准 JSON，外部工具可直接消费数据集。

## 后续扩展建议

- 把看房记录、电话核验记录、报名材料状态拆成独立 JSON 模块。
- 把推荐策略权重外置为配置文件，避免硬编码在页面生成脚本里。
- 把高德增强脚本纳入固定 pipeline，记录 POI 匹配分数和地址编码比例。
- 后续扩展新区域时，先补区级源数据、贝壳板块、政策来源，再进入标准数据和推荐策略。
